# Session Persistence, Projections, Recovery, and Forking

HEAD `00102833` (master, 2026-09-22). This tree is newer than the assignment sheet: `session-persistence-jsonl/src/index.ts` is **1725** lines (not 1631), `session-projection/src/index.ts` is **714** (not 682). All claims read from current source unless marked UNVERIFIED.

## Headline findings (most surprising first)

1. **No hashing, MAC, or hash-chaining exists anywhere in the session log.** Integrity rests on `seq = log.length` contiguity, one-pass lossless-JSON snapshot validation (a stateful getter cannot feed validation one value and storage another), and stat-derived revision tokens. The only SHA-256 in the persistence path is `historicalCorpusRevision` — a digest over *paths + stat identities* of all generations, used solely to invalidate listings when a pre-v4 generation exists (`session-persistence-jsonl/src/index.ts:1038-1053`). Event bytes are never digested: tampering preserving JSON validity, seq contiguity, and file size/mtime/ctime is undetectable.
2. **The event bus deliberately leads the event store.** `append` pushes to the in-memory log, *then* invokes `session/event` callbacks (`packages/core/session/src/index.ts:752-764`); the JSONL backend buffers each event and arms a **200 ms** batch timer (`storage.ts:36`, `274-281`). Order is preserved (both paths serialize on one per-handle promise chain), but a crash in that window loses events the bus already observed; `session/flush` closes it.
3. **Fork inherits almost no header policy.** The child header gets only `cwd`, `parentSession`, `isSeeded: true` (`index.ts:1246-1254`); `delegationDepth`, `origin`, `agentPreset`, `createdAt` are **not** propagated, so a fork of a depth-2 subagent reads as top-level.
4. **Crash recovery and fork share one repair engine and one set of error codes.** `TOOL_OUTCOME_UNKNOWN` / `TOOL_NOT_STARTED` are identical for both causes; only the model-visible prose and the `turn/end` reason differ (`packages/core/session/src/repair.ts:32-44`).

## 1. Session record, append() contract, sequence numbers, freezing

The log is an append-only array of `SessionEvent` (`index.ts:445`): `{ type, seq, time, data, surfaceOp?, sourceEventSeqs?, ignorable? }`. `SessionEventMap` (`types.ts:281-428`) defines the vocabulary (turn/step boundaries, messages, tool call/result, `request/header`, `request/context`, `session/end-seed`); it is merge-extensible, while `KNOWN_SESSION_EVENT_TYPES` is a **generated** set of 58 in-repo types (`known-event-types.ts:22-82`).

`append()` (`index.ts:720-771`) assigns `seq = SessionSeq(this.log.length)` and `time = Date.now()` — contiguity is structural, not checked. `data` and surface metadata are each snapshotted in one iterative pass that rejects any non-JSON value *before* the log mutates. `validateSessionEventData` then rejects noncanonical headers, developer-role/tool-change coupling, and a `tool/result` error without `message.isError === true` (`surface.ts:172-226`), and `surfaceManager.validateNext(event)` plans the surface transition *before* the push, so a bad event cannot partially mutate it. Reentrant append during the publication boundary is rejected. Once pushed the append is **committed**: observer failures are logged and contained per listener and cannot change the return value. Message-carrying data is deeply frozen — `adoptSessionEvent` freezes without copying, `snapshotSessionEvent` clones first (`index.ts:169-200`) — so reading `event.data` never exposes the caller's mutable input. The synchronous `snapshotEvents()`/`eventAt` readers are `@deprecated` since 2026-09-09 (new calls prohibited; existing sites carry `oxlint-disable`).

`SessionHeader` (`types.ts:94-131`) lives **outside** the log: `version` (always `SESSION_FORMAT_VERSION = 4`), `id`, `createdAt`, `cwd`, `parentSession`, `isSeeded`, `origin?`, `delegationDepth?`, `agentPreset?`. On disk it is the first JSONL record with `type: 'session'` (`format.ts:83-94`). The exact fork cut is *not* in the header — it rides on the last tagged `session/end-seed` event. **Freezing is the only content-integrity mechanism; no per-event hash, chain, or signature** (UNVERIFIED: nothing in `packages/session/**` adds one).

## 2. deriveMessages() / foldSurface: primary, derived, cached

**(a) Primary:** the event log array; everything else is derived or cached.

**(b) Derived — the surface.** `SurfaceManager` (`surface.ts:617-718`) maintains `nodes`, the ordered seqs of message-producing events after applying `surfaceOp`. Five types are surface-eligible (`surface.ts:50-56`); `surfaceOp` is `'append'` or `{ op: 'replace', startSeq, endSeq }` (inclusive-inclusive), which splices the shadowed range out of `nodes` (`surface.ts:575-591`). Every transition validates structurally — source-reference density/orderedness/uniqueness (`assistant/message` may not carry them at all); tool/result rewrite permission (content may change, `callId`/identity may not, compared with content nulled, `surface.ts:461-491`); system-head rewrite (node 0 holding a `system/message` may be rewritten only by a `system/message` over exactly that node); developer-header tool-addition rules.

**(c) Cached.** `deriveMessages()` (`index.ts:842-863`) walks `surface.nodes` and projects each. Invalidation is by generation counter: `replaceGeneration` counts positional replacements; `contentGeneration` also counts plugin-owned message projections (`surface.ts:251-258`, `579-583`). A mismatch resets the whole cache; otherwise it extends over `nodes.slice(derivedNodes)` — O(new nodes). The returned array is fresh per call; the `Message` objects inside are shared and deep-frozen. An empty-content assistant message (a max-tokens step hosting only usage) projects to `null` and is omitted.

`foldSurface(events, projections)` (`surface.ts:600-615`) is the stateless full-log counterpart. `SurfaceManager` deliberately **retains no replacement history** (`surface.ts:619`): a human transcript must use `isAppendSurfaceEvent` / `isReplacementSurfaceEvent` over the raw log, because the model-visible surface shadows replaced conversation.

**Plugin-owned message projections** (`registerMessageProjection`, `index.ts:924-932`): a pure interpreter for a plugin event that changes *existing* message content without changing node membership or message identity (`surface.ts:34-47`). Registration is a fiber-owned effect; a duplicate type throws; disposal makes sessions that used it **refuse further derivation** (`surface.ts:705-717`). Exactly one event type requires one today: `MESSAGE_PROJECTION_EVENT_TYPES = { 'image/offload' }` (`known-event-types.ts:85-87`), shipped as `currentSessionMessageProjections` (`session-format-catalog/src/message-projections.ts`), consulted in `planSurfaceEvent` *before* the surface-op branch (`surface.ts:529-537`). Also cached incrementally: `requestHeader()` and `requestContext()` (`index.ts:786-815`).

## 3. Crash recovery: interruptedTurnClosers and the conservative wording

`openTurnClosers(events, cause)` (`repair.ts:63-164`) is one shared scanner for both producers. It tracks an open turn/step cursor and `pendingCalls` keyed by `ToolCallId`, registered from `assistant/message` tool-call blocks and annotated with the `tool/call` seq when it lands; a matching `tool/result` clears it, and `pendingCalls` resets at every `turn/start`, `turn/end`, and `step/end` so earlier calls cannot leak into tail repair. A balanced or empty log returns `[]`.

For an open tail it appends, in order: one synthetic error `tool/result` per unmatched call in the *open step* only; `step/end` if a step is open (a `turn/end` over an open step is an invariant violation); `turn/end` with `reason: { kind: cause.kind }`. Sequences continue the log, **timestamps reuse the last real event's time**, and the synthetic id is `${cause.kind}-tool-result-${callId}-${seq}`. Calls in already-closed steps are left untouched, including failed calls already missing results — repair closes only the genuinely open tail.

**The exact conservative wording** (`repair.ts:35-44`), for `interrupted` + a started call:

> "The tool call was interrupted after it was recorded, but no result was durably recorded. Its outcome is unknown. Decide whether to retry from the tool semantics: retry only if the operation is read-only or idempotent; if it may have side effects, first verify external state or ask the user. Do not retry blindly."

The not-started variant says the call was interrupted before the Harness recorded it as started and may simply be retried. The `forked` variants replace "interrupted" with "the parent session may have completed it after the fork point" — same retry discipline, same two codes (`TOOL_OUTCOME_UNKNOWN` / `TOOL_NOT_STARTED`), the started variant citing the `tool/call` seq via `sourceEventSeqs`.

Three call sites: agent-loop resume (`packages/core/agent-loop/src/index.ts:852-863`: read → closers → `handle.append(closers)` through the same write handle as an ordinary batch); read-only cold reads (`session-query/session-query/src/cold-read.ts:55`: appended in memory, **nothing written back**); fork seeds (§6).

## 4. Write lease and single-writer enforcement

**Cross-process (`session-persistence-jsonl/src/lease.ts`):** a kernel lock on `session.lock` beside the log, held for the whole life of a write handle. POSIX takes non-blocking `flock(2)`; contention (`EAGAIN`/`EWOULDBLOCK`) maps to `SessionAlreadyOwnedError`. Because a POSIX lock names an *inode*, acquisition re-stats and verifies the locked inode is still the file at the path, retrying up to 3 times (an unlinked-and-recreated lock file has a fresh inode; a lock on the orphan proves nothing). Windows holds a named kernel semaphore derived from the path — no file, no handle, so readers, searches, and directory removal proceed freely. Release closes the descriptor/handle; **the POSIX lock file is never removed** (it preserves the stable inode later lockers verify against). The kernel releases on any process death, so a crashed holder never blocks a successor. There is **deliberately no expiry**: a live-but-wedged holder keeps the lock until its process exits, because expropriating a stalled writer whose resumed appends would tear the log was rejected. Advisory `flock` is unreliable on NFSv3 — such a root degrades toward in-process-only exclusion. Deleting a live session's lock file forfeits exclusion on POSIX; the harness never does so.

**In-process only (`storage.ts:391-500`):** `JsonlBackendTracker.writers` maps `SessionId → handle | null`; `claimWrite` throws `SessionAlreadyOwnedError` on a duplicate, `registerCreated` throws `SessionAlreadyExistsError`; a `null` slot marks a claim mid-construction. Before materialization this map is the *only* guard. The browser worker **stubs the flock entry to immediate success** because its in-process claim already excludes every writer.

Timing: `open(id, 'write')` acquires the lock up front (`index.ts:377-399`); a `create` handle acquires it lazily at its first materializing write (`storage.ts:321-343`, `352-354`) — an unmaterialized session leaves **no** filesystem footprint, and the handle keeps the lock through close even if materialization then fails.

## 5. Flush/durability, ordering, torn lines

**Flush seam.** `SessionStore.flush(session)` is the *only* sanctioned entry (`index.ts:1163-1193`): it dispatches the awaited parallel `session/flush` with the carrier captured at `enter`, awaits all listeners with `allSettled`, throws the first rejection after every listener settles, and returns whether at least one participated. `dsh-session-checkpoint-policy` is the semantic owner: it checkpoints before adapter dispatch (`llm/stream`), before top-level tool bodies (`tools/execute`), and at `agent/pre-step` — fail-closed, so a flush failure prevents the downstream side effect.

**Backend durability.** `persistContiguous` (`storage.ts:319-343`): contiguity check against the handle cursor → torn-tail repair → `persistBatch` → advance cursor. `appendLines` (`index.ts:1324-1352`) writes then `handle.sync()` (fsync); on any write/sync failure it **truncates back to the pre-append size before rethrowing**, because the unchanged cursor will retry the batch and partial bytes would duplicate sequence numbers. A `flush()` on an unmaterialized session materializes a header-only artifact (`storage.ts:203-212`). Close always drains the routed buffer first.

**Can the bus and store diverge?** In time and on crash — yes; in content or order — never. `enqueueLive` stores a `structuredClone` (`storage.ts:275`) of an already deep-frozen event, and live drains share one per-handle chain with explicit appends, so serialization is total. The bus leads by up to 200 ms plus drain time, and a crash there loses buffered events (with the in-memory log). A failed background drain pauses the timer and **retains the batch in order** (`storage.ts:294-316`) so `session/flush` retries loudly.

**Append-only in practice?** Within a generation: append, plus two deliberate non-append operations — rollback truncation on partial write failure, and torn-tail truncation before the next append. Across generations: strictly immutable; migration writes only the final current target (`session.v4.jsonl.zstd`) and never moves, replaces, or deletes a committed generation (note `2026-08-31-released-session-format-migrations.md:114`). POSIX publication is `link()` + directory fsync (EEXIST means another process won); Windows is no-overwrite write-through `MoveFileExW`.

**Torn-line handling.** Plaintext: `SessionLogScanner` searches newlines, retains an incomplete final fragment, and `finish()` drops a trailing newline-less record reporting `committedBytes` (`format.ts:417-475`). Zstandard: frame boundaries are located, complete frames decode through one reused synchronous decoder yielding every ~500 ms, and a **torn final frame's already-flushed complete records are recovered** via `decompressZstdPrefix` as `recoveredTail` with `tornTruncateTo = tornStart` (`index.ts:938-1022`); the write path then truncates the torn bytes and durably rewrites them (`storage.ts:328-337`), logging "recovered from a torn tail; incomplete tail bytes were discarded". Recovery modes: `strict` throws immediately on an unparsable/invalid row; `recoverable` records the issue, suppresses subsequent events, and rethrows at the next `turn/end`, so the recoverable prefix ends at a turn boundary (`format.ts:478-521`). `assertV4RowAdmission` runs *before* suppression so an unsupported current-format row always throws. A handle also refuses a stored log that shrank below a previously observed prefix (`storage.ts:165-180`).

## 6. Fork

`SessionStore.fork(source, boundary?, childSessionId?)` (`index.ts:1237-1255`) with `buildForkSeed` (`packages/core/session/src/fork.ts:21-29`):

- **Copied:** the inclusive event prefix `events[0..boundary]`, detached deep-frozen (mutating a child event throws `TypeError`).
- **Marked:** `session/end-seed` with `data: { inherited: true }` at `boundary + 1`, reusing the boundary event's timestamp, inserted **before** the synthetic closers.
- **Closed:** `openTurnClosers(prefix, { kind: 'forked' })`.
- **Counted:** `inheritedEventCount` counts **only copied source events**; the marker and closers are child-owned.
- **Referenced:** `parentSession: source.id`; lineage tracing walks it across the corpus.
- **Reset:** `delegationDepth` (to 0), `origin`, `agentPreset`, `createdAt`. **Guards/approvals/permissions inherit only insofar as they are logged events** (`approval/asked|decided|policy`, `permission/preset`, `sandbox/mode` are all in `KNOWN_SESSION_EVENT_TYPES`); pending, unlogged approval state does not. The header carries no policy fields: `sandboxMode`/`approvalPolicy` are explicitly retired and refused (`format.ts:105-110`).
- **IDs:** caller-supplied or store-minted (`session-<n>`); child seqs equal parent seqs through the cut and **diverge after it**; synthetic ids deterministic (`forked-tool-result-<callId>-<seq>`). A nested fork retains ancestor markers, and the constructor requires the supplied cut to identify the **final** inherited marker (`index.ts:603-610`).
- **Boundary rules:** omitted boundary means the source's last event (empty source → empty child, `inheritedEventCount = 0`); an explicit boundary must be an existing non-negative safe integer matching a contiguous seq, else `SessionForkError` with `INVALID_BOUNDARY`; taken child id → `SESSION_ALREADY_EXISTS`; unknown id → `SESSION_NOT_FOUND`; a non-live instance → `SESSION_NOT_LIVE`.
- **`session/end-seed` is the durable twin of `firstLiveSeq`** — the mechanism by which a bracket owner (e.g. `compaction/start`) distinguishes a dead inherited marker from a live one. It is explicitly **not** a liveness signal about other writers (`types.ts:403-427`).

## 7. Projections

Two unrelated systems. **(A) Message projections** (§2) — plugin-owned, in-`Session`, affect derived messages. **(B) `ctx.sessionProjections`** (`session-projection/src/index.ts`) — the domain-state seam: a `ProjectionDefinition` is `{ key, stateSchema, init(header, inheritedEventCount), apply(state, event), wire?, stateVersion }`. Functions must be **synchronous** (an async unit would tear the carriers' consistency cut) and `state` plain JSON. `apply` MUST return the same reference when uninterested — `Object.is` equality yields zero downstream work (`index.ts:48-93`).

- **Drive:** the registry subscribes to `session/event` once and passes every committed event to every unit. Cells build lazily — a unit registered after events flowed folds `init` over the in-memory log on first touch (`index.ts:656-704`).
- **Watermarks:** each `UnitCell` carries `observedSeq` (the last event *passed through* `apply`, regardless of change). `snapshot.asOfSeq` is `cursorBefore(session.seq)`; `cachedSnapshot` takes the lowest observed watermark and is explicitly a *hint, not a baseline* (`index.ts:362-380`).
- **Change feed:** `onChanged` fires only when the raw `view` result changes by `Object.is` — a two-slot view buffer suppresses publication across internal-only state changes (`index.ts:686-700`).
- **Concurrency:** registration is ref-counted (N presets mounting the same unit share it; the last one out removes the key); a same key with a different `stateVersion` is refused (`index.ts:159-174`, `253-293`).
- **Incremental vs rebuild:** live reads advance cells contiguously and throw on a missing seq (`index.ts:633-654`). Cold reads use `restore(checkpoint, events, baseSeq, …)` whose `restoreFloor` is **one event below** the lowest usable watermark — load-bearing, because it proves how far the stored log still extends, so a log that shrank below a row's watermark (crash-repair truncation) is detected instead of serving the stale row (`index.ts:409-440`).
- **Idempotency:** rows are keyed `(sessionId, key, ver, seq, val)`; a `ver` mismatch discards rather than migrates; `hydrate` installs a restored cut for later publication to reuse (`index.ts:552-595`).

**Persisted cache** (`session-projection-cache`): the `session_projcache` domain, version 7, `compatibleVersions: [3,4,5,6]`, `per-record` layout, `invalidRecords: 'backup-and-skip'` (`spec.ts:101-108`). Writes are throttled (`writeEveryEvents`, `writeIntervalMs`) plus **three mandatory points** — `session/created`, `turn/end`, `session/disposed` — all fail-soft (`index.ts:311-362`). `write()` snapshots the registry cut, **flushes the log first**, then puts the record, so the cache can lag the log but never lead it. Records are identity-bound (`formatVersion`, `createdAt`, `cwd`, `isSeeded`, `inheritedEventCount`) — a session id names a slot, not a lifecycle; a predecessor record may expose only its `title` as a zero-I/O listing hint.

**Existing projection keys** (merged repo-wide): `sessionStats`, `turnOutline`, `title`, `usage`/`breakdown`, `goal`, `todo`, `plan`, `schedule`, `subagentCatalog`, `modelSelectionState`, `permissionPresets`, `sandboxPolicy`, `agentPreset`, agent/tmux/time context, `llmRetry`. The shipped folds show the seam's discipline: `sessionStats` counts `step/end` (not `assistant/message`) because the loop appends exactly one per entered step in a `finally`, so completed/failed/cancelled/max-tokens steps all land one (`session-stats/src/projection.ts:5-22`); `turnOutline` anchors entries on `turn/start` because its seq is the load-through target for a jump (`session-turn-outline/src/projection.ts:6-18`).

**`session-log-deepseek`** keeps *accepted sequence watermarks in the canonical log itself*: `session-log-deepseek/delivery-accepted` records `{ sessionId, sessionFormatVersion, throughSeq }`, and `acceptedThrough(session)` folds them incrementally (WeakMap cache, resumable scan, format-version filtered) so restart recovery can conservatively resend uncertain tails without another store (`session-log-deepseek/src/index.ts:113-152`). The acceptance event is appended in `accept()` after a 2xx; the file carries two TODOs (explicit wire result for stale sessions; an immediate checkpoint if duplicate replay after a 2xx crash window becomes unacceptable) — **experimental/incomplete by its own admission**.

## 8. Format migration chain v0→v4, ignorable marker, session-query API

`SESSION_FORMAT_VERSION = 4`. The bump rule is writer-oriented: bump only for structural changes (header shape, envelope, core event semantics, or the surface mechanism — the `SurfaceEventType` set and `SurfaceOp` variants); **adding an ordinary event type does not bump**, because `ignorable` covers vocabulary growth (`types.ts:68-88`).

The chain is codecs v0–v4 plus four adjacent edges, build-static and generated into `sessionFormatCatalog` (`session-format-catalog/src/generated.ts:16-45`). `CompiledSessionFormatChain` validates a unique, gap-free edge set once and connects stages in reverse so a row flows `v0→v1→v2→v3→v4→collector` with no intermediate artifact array (`session-format/src/chain.ts:41-127`). Stages are **stateful and synchronous** (v0→v1 tracks message/retry identity; v1→v2 buffers one unsettled attempt and maintains an old→new seq map). Filenames: v0 is `session.jsonl[.zstd]`, later generations `session.vN.jsonl[.zstd]` (`session-format/src/filename.ts`). V3→V4 is header-only by default and **refuses without explicit child evidence** (an empty array declares no children); `createSessionFormatV3ToV4(children)` binds it and appends missing `subagent/catalog` entries at `finish()` (`session-format-v3-to-v4/src/migration.ts:15-39`).

**The `ignorable` forward-compat marker** (`types.ts:500-516`): absent means *required*; a reader meeting an unrecognized type without it **must refuse** rather than silently drop, while a writer sets `true` only on purely informational records. Current-format reads retain unknown `ignorable` events verbatim, and the storage contract refuses loudly otherwise — "it was likely written by a newer harness" (`storage-contract.ts:75-80`); V3→V4 namespaces them to `plugin:<type>`, payload and coordinates opaque (`extension-identities.ts:71-77`). Historical v0/v1/v2 migration **refuses** an unknown type even when marked ignorable, matching `docs/subsystems/persistence.md:189`. One retired shape under a known type is also refused: `request/header` with `reason: 'fallback'` (`storage-contract.ts:83-92`).

**session-query API** (`session-query/src/index.ts`): backend-independent exact reads — `observeSession`, `listSessions`, `readSession` (replay-validates via a detached `Session.create`), `filterSessions`, `readTitle`/`readTitleSnapshots`, `listEvents`, `filterEvents`, `readSurface`, `traceSession` (ancestry/descendants), `traceEvent` (replacement + cited-source chains), `readEvent` (bounded window, `readWindowMax`), plus abstract `searchSessions`/`searchEvents`; `readColdSessionLog` is the shared cold recipe. The corpus is **live-preferred**: a known live target never consults persistence, so an optional backend failure cannot make current in-memory history unreadable (`corpus.ts:91-120`), and a live/persisted header conflict is asserted rather than silently merged. `session-query-sqlite` is the disposable FTS5 read model: schema version 8 (incompatible versions reset in place), an `application_id` guard (`0x44534851`) against foreign databases, `persisted_docs`/`temp.live_docs` FTS5 tables, generation-numbered cursors that invalidate on corpus change, and full reconciliation under a serialized queue with `BEGIN IMMEDIATE`/`COMMIT`/`ROLLBACK` (`session-query-sqlite/src/index.ts:383-493`).

## Implications for a regulated SAS→PySpark migration verification platform

- **The log is a defensible audit record but not a tamper-evident one.** Contiguity, JSON validity, and deep freezing give strong *accidental-corruption* guarantees and deterministic replay, but no content digest. If a regulator requires integrity proof, add an external witness (hash each durable batch and chain it) at the single `SessionHandle.append`/`persistBatch` seam — a localized change.
- **`seq` is a perfect monotonic cursor** for an independent verification index; the projection-cache `(key, ver, seq, val)` discipline and `restoreFloor`'s one-below anchor are directly reusable patterns for a checkpoint that never claims more than the stored log proves.
- **Synthetic events are first-class and must be distinguished.** `interrupted`/`forked` `turn/end` reasons and the two `TOOL_*` codes are honest "outcome unknown" markers; treat any log containing them as requiring external corroboration — exactly the semantics the model-visible prose prescribes.
- **"Committed" ≠ "durable."** Any verification gate must await `ctx.sessions.flush(session)`, or lean on the checkpoint policy's pre-side-effect barrier, which is fail-closed at the tool-body boundary — the right hook before an irreversible transformation.
- **Fork is the branching primitive for what-if verification runs**, but assume policy state resets (depth, preset, pending approvals) and that only logged policy events carry forward.
- **Format migration is deterministic, streaming, and never mutates evidence** — v0→v4 with per-parent child evidence and strict/`recoverable` recovery keeps a historical corpus verifiable across harness upgrades; `ignorable` provides forward compatibility without silent data loss, the correct posture for long-lived regulated artifacts.
- **`session-query` is a ready-made read model** (lineage tracing, surface reconstruction, event windows) over a live-preferred corpus, with a disposable SQLite FTS5 index whose schema resets in place — a verification UI without risking the authoritative log.
